# ADR-001 — Orchestrator as a Node.js sidecar of the Tauri shell

- **Status:** Verified on a GitHub-hosted Windows runner. **Not yet verified on a physical Windows device** (Lenovo Legion).
- **Date:** 2026-11-01
- **Supersedes:** the "pending spike" note for ADR-001 in `DECISIONS.md`.

## Decision

The orchestrator runs as a separate Node.js process (the _sidecar_) started by the Tauri (Rust) shell. The Rust side owns the process lifecycle; the React frontend never talks to the sidecar directly, only through Tauri commands.

## Verified architecture (as implemented in Phase 0)

```
React (webview) ──invoke──▶ Tauri command (Rust) ──stdin/stdout NDJSON──▶ Node sidecar ──▶ SQLite (WAL)
                                                                              └─ Orchestrator + StubAdapter
```

- **Sidecar bundle** (`scripts/build-sidecar.mjs` → `services/orchestrator/sidecar-dist/`, git-ignored): `node(.exe)` (a copy of the build machine's Node), `sidecar.mjs` (esbuild bundle of orchestrator + workspace packages), `better_sqlite3.node` (native module), `drizzle/` (migrations). No `node_modules`.
- **Native module loading:** `openDatabase(path, { nativeBinding })` passes an explicit path to `better-sqlite3`; migrations folder is passed with `--migrations`.
- **Protocol:** newline-delimited JSON, one request/one response per line, schemas in `packages/contracts` (`SidecarRequest`/`SidecarResponse`). Methods: `health`, `runStub`, `queryTask`, `shutdown`. stdout is reserved for the protocol; logs go to stderr.
- **Process launch:** Rust `std::process::Command` with an argument array (no shell), `CREATE_NO_WINDOW` on Windows (`apps/desktop/src-tauri/src/sidecar.rs`).
- **Lifecycle / cleanup:** protocol `shutdown`; closing stdin also makes the sidecar exit; Rust `Drop` and `RunEvent::Exit` shut it down; the sidecar handles SIGTERM/SIGINT.
- **Selftest mode:** with `AGENT_STUDIO_SELFTEST_OUT` set, the frontend runs `system_health` → `sidecar_health` → `sidecar_run_stub` through real Tauri IPC, writes a report and the app exits. Inactive otherwise.

## Problems found by the spike

1. **`better-sqlite3@13.0.3` cannot be installed on `windows-latest`.** It has no `prebuild-install` step, so `node-gyp` compiled it and failed to find Visual Studio 18 (run `41260106056`, job `124711427401`). **Decision:** pin `better-sqlite3@12.11.1` (`prebuild-install || node-gyp rebuild`); install then succeeded (run `41260535795` onward). Re-evaluate on every upgrade; consider a Windows prebuild check in CI (the `desktop-smoke` job already acts as one).
2. **Line endings:** Windows checkouts used CRLF and failed `prettier --check`. Fixed with `.gitattributes` (`* text=auto eol=lf`).

## Consequences and limits

- The bundle contains a full Node binary (**119.1 MB** on Linux; the Windows size was not recorded) plus a 2 MB native module. Installer size has **not** been measured: the Tauri installer (NSIS/MSI) was **not built** in Phase 0 (`--no-bundle`).
- `bundle.resources` / Tauri sidecar packaging and code signing of the bundled `node.exe` are **not** done. In the smoke test the `sidecar/` folder is copied next to the exe by the CI script; `AGENT_STUDIO_SIDECAR_DIR` overrides the location.
- Process cleanup relies on stdin closure, `kill` and `Drop`/`RunEvent::Exit`. A hard kill of the _Rust app_ (e.g. crash) is covered only by the sidecar's stdin-closed handling; **Windows Job Objects are not implemented** (Phase 4, ADR-002). Grandchild processes of future agents are not covered yet.
- stderr of the sidecar is discarded by the Rust side in the spike (`Stdio::null()`); a log sink is required before real adapters.
- The IPC is synchronous request/response; streaming events to the UI are Phase 1.
- Shipping the build machine's `node.exe` ties the bundle to that Node version (22.23.4 in CI); pin and verify the runtime binary (checksum/signature) before release.
